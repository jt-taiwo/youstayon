# Overview
This document bridges the gap between the application architecture and the deployment architecture. It defines all shared infrastructure that every module depends on. The goal is to ensure that the same codebase runs consistently across local development, staging, and production with only configuration changes.

# 1. Purpose

It specifies:

* Configuration management
* Environment strategy
* Caching

* Scheduling
* Storage
* Logging
* Monitoring
* Notifications
* Third-party integrations
* Secrets management
* Development environments
* Operational infrastructure

The objective is to provide a consistent, secure, scalable, and maintainable operational foundation.

---

# 2. Infrastructure Principles

All infrastructure must adhere to the following principles:

* Infrastructure is configuration-driven.
* Secrets are never committed to source control.
* Services communicate through stable interfaces.
* Stateless application servers.
* Infrastructure components are replaceable.
* Environment parity where practical.
* Automation over manual operations.
* Observability by design.

---

# 4. Environment Variables

Environment variables are the primary runtime configuration mechanism.

Examples:

```dotenv
APP_NAME=YouStayOn
APP_ENV=local
APP_DEBUG=true
APP_URL=http://localhost

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=youstayon_dev
DB_USERNAME=root
DB_PASSWORD=

CACHE_STORE=database
QUEUE_CONNECTION=database

FCM_PROJECT_ID=
FCM_CREDENTIALS=

SANCTUM_STATEFUL_DOMAINS=
```

Sensitive values shall never be hardcoded.

```text

```

Future:


---

## Queue Types

## Queue Principles

## Engineering Decisions Adopted

To align with our earlier project decisions, the following are now part of the architecture:

* **Local database:** XAMPP MySQL during development.
* **Database source of truth:** Laravel Migrations → Seeders → Factories → Generated SQL export.
* **Queue driver (MVP):** Database, with Redis as the planned upgrade path.
* **Cache driver (MVP):** Database, with Redis planned for production-scale deployments.
* **Deployment philosophy:** Configuration-driven, with no environment-specific code branches.
* **Feature implementation:** Vertical slices after the architecture phase, while preserving the DDD modular structure.
